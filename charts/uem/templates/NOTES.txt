1. Watch the initialization jobs finish (they run automatically after install):

   kubectl get jobs -w

   The "emqx" job provisions the EMQX API key and rules, then the "uemctl"
   job runs schema migration, Kafka topic creation and tenant init. Application
   pods wait for these jobs before starting.

2. If you did not enable the built-in Ingress, configure routing on your own
   ingress controller according to docs/ingress-routing.md. In summary:

   https://{{ .Values.domain }}/                 -> www:80          (console)
   https://{{ .Values.domain }}/api,/partner     -> bff:80
   https://{{ .Values.domain }}/zs               -> devices:80
   https://{{ .Values.domain }}/apple,/MDMServiceConfig -> apple:80
   https://{{ .Values.domain }}/ManagementServer,/EnrollmentServer -> windows:80
   https://{{ .Values.domain }}/files,/file,/dispatch -> file:80
   https://{{ .Values.domain }}/sse/rcw,/wss/rcw     -> remote-proxy:80

   MQTT (tcp {{ .Values.mqtt.tcpPort }} / tls {{ .Values.mqtt.sslPort }}) and the
   remote-control STUN/TURN ports must be exposed directly to devices (LoadBalancer
   or NodePort), not through an HTTP ingress.

3. Check pod status:

   kubectl get pods -l app.kubernetes.io/instance={{ .Release.Name }}
